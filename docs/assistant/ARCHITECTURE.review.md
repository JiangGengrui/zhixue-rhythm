## 结论

结构可用，但有 1 处**会直接导致线上连接截断**的接缝没写（`__sent` 握手与流式段抛错），3 处与既有代码/指标对不上（首字延迟无字段、路由判定写法含糊、清理触发点不成立）。以下 8 条已修正，3 条留待你决策。

## 已修（8）

| # | 问题 | 证据 | 处置 |
|---|---|---|---|
| 1 | 流式端点进入后抛错会被外层 `catch` 二次 `sendJson`，撞 `ERR_HTTP_HEADERS_SENT`，用户看到连接截断而非错误码 | `index.mjs` API 分支统一 `sendJson(res,200,result)`，仅 `__sent` 可跳过 | 新增 §2.8 三条硬约束：流内异常不外抛、失败也要发终止帧、20s 服务端计时 |
| 2 | 「首字 P50 < 1.5s」在数据模型里无字段可算，指标不可测 | `assistant_events` 原只有 `latency_ms` | 加 `first_token_ms`（需同步 SPEC §7.3） |
| 3 | 「规则/模型判定为数据类」二义，实现时必分歧 | SPEC §5.1.1 已定四级有序表 | 改为规则表判定，模型不参与路由，并在 §2.3 复述 |
| 4 | 「启动时惰性清理」在单容器长跑下形同不清理 | 云托管容器可连续运行数月 | 改为「启动 + 每日首个请求」双触发 |
| 5 | 断网时助手行为未定义，与既有 `offlineQueue` 的关系未交代 | `src/data/offlineQueue.ts` 只服务打卡类写操作 | 新增：不发请求、不入队、本地直回 |
| 6 | 安全面空缺（Cookie 属性、CSRF、注入体积） | `auth.mjs`：`HttpOnly; SameSite=Lax`，**无 `Secure`** | §2.8 记明复用 Lax 故不引 CSRF token；Cookie 补 `Secure` 列为阶段 1 顺手项；500 字上限写明是体积护栏 |
| 7 | 配额按哪个时区的「日」未定 | SPEC 多时区非目标 | 明确按客户端上报日期，服务端只校验格式；写清「改系统时间可绕过」的代价 |
| 8 | 一句无证据的「已实测 1.5s 首字」 | 项目内无该项实测记录 | 改为「目标里的 1.5s」，不虚构实测 |

## 已核验无需动作（2）

- **备份覆盖**：`scripts/backup.mjs` 是整库 `copyFileSync`，新增三张表自动被备份，不需要改脚本。
- **前端状态层**：`store.ts` 是单一状态树 + `api.ts` 统一 `ApiError`，流式问答走独立函数不并入 `store`，不会出现「一次 SSE 触发全树重渲染」的问题。
