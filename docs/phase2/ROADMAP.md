## 2. 收尾阶段（v1.5.1）做了什么

- **结构分层**：`src/ui/` 收纳共享视觉层；`docs/` 按主题分 `api/ops/design/assistant/architecture/screenshots/phase2`；`scripts/probes/` 隔离一次性探针。
- **文档校准**：README 用例数统一为 188、`CODEBUDDY.md` 目录树纠错、运维手册按当前部署事实重写、助手知识库 deploy 条目纠错、`npm run shots` 补别名。

**明确没做**（下一阶段再碰）：业务逻辑零改动；`docs/product/*.docx` 二进制交付物未同步；仓库 About 的 Website 链接未设置。

## 3. 阶段二范围

### P0 · 先修地基（不做完不接新功能）

1. **数据持久化**：容器内 SQLite 是实例本地存储，重新部署即清空。改为挂载持久卷，或迁 Postgres（接口契约已用 OpenAPI 固化，迁移不影响前端）。
2. **部署正式化**：固定域名 + HTTPS，一条命令发布；沙箱只作演示备份。
3. **健康检查端点**：当前没有 `/api/health`，靠 `/api/visit` 与 `/api/state`（401）间接判断，应补一个显式的只读健康接口。
4. **备份与恢复演练**：`npm run backup` 已有，但缺少定时任务与一次真实的「备份 → 恢复 → 校验」演练记录。
5. **测试日期硬化**：`server/api.test.mjs` 里大量写死 `2026-11-02` / `2026-11-09` 与 `deadline: 2026-12-19`。v1.5.1 已修掉两条已经失效的（锁定、重排顺延），其余会在 12 月中旬陆续变成「过去周」而失败。应统一改成相对当前周的动态计算，否则 CI 会在无人改代码的情况下变红。

### P1 · 产品能力

5. **多端并发**：当前后写覆盖（README 已知限制 2）。最小方案是块级版本号 + 乐观锁，冲突返回 `E4xxx` 并由前端提示重取。
6. **重排扩到未来周**：现在只作用本周已排任务（已知限制 3）；未来 7 天负载增幅超 20% 时策略直接置灰，体验上是断的。
7. **移动端与 PWA**：布局已有单列断点，但离线仅覆盖操作队列，静态资源未做离线缓存。
8. **助手增强**：历史会话列表（`DECISIONS.md` D8.1 已留端点未接）、向量检索（SPEC R12 范围外，需重新立项）。

### P2 · 运营

9. 留言/反馈的运营侧视图与灰度开关。

### 边界（沿用 `CODEBUDDY.md`）

不引入 Express/Koa/Prisma、不引 UI 组件库、不改 Cookie `Secure` 属性（需单独立项）。

## 4. 里程碑与验收判据

| 里程碑 | 内容 | 验收判据 |
|---|---|---|
| M1 · 数据地基 | 持久卷或 Postgres；固定域名 + HTTPS | 重新部署后旧数据仍在；`docs/api/openapi.yaml` 契约不变而前端无改动 |
| M2 · 可观测 | `/api/health`、结构化请求日志、错误聚合 | 健康接口 200 且含版本号；一次人为 500 能在日志里定位到路由与用户 |
| M3 · 备份演练 | 定时备份 + 恢复脚本 | 用最近一份备份恢复到空实例，`/api/state` 数据条数与备份前一致 |
| M4 · 并发与重排 | 乐观锁 + 重排扩周 | 两个客户端同时改同一块，后改方收到冲突码并可见提示；重排可作用于下周 |

## 5. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 沙箱被回收 | 演示链接失效 | M1 换固定域名；README 保留 CloudBase 部署路径作为备份 |
| 数据丢失 | 演示期间用户数据清零 | 持久卷 + 每日备份，M3 演练兜底 |
| 单人开发，范围膨胀 | 关键路径阻塞 | 严格按 P0 → P1 推进，P2 随时可砍 |
| 重构引入回归 | 已交付功能被破坏 | 188 条自动化 + e2e 兜底，改结构必须全绿才提交 |
| 文档再次漂移 | 交接成本上升 | 每次改接口/部署/脚本，同步 `docs/api`、`docs/ops`、`CODEBUDDY.md` |

## 7. 建议的第一个任务

**M1 数据地基**，理由：现阶段所有新功能都建在一份「重新部署即清空」的库上，越晚迁移，后续数据迁移成本越高，且演示中途丢数据的风险一直悬着。功能可以晚一周，地基不能。
